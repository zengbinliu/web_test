# web_test
本仓库包含web测试全流程skills以及相应技巧


## 需求分析skill(review-product-requirements)
用于对需求文档进行分析，排查出不清晰的需求点以及矛盾点。

本skills，基于codex，参考了https://github.com/Spacey6849/AgentSkills/blob/main/.claude/skills/requirements-analysis/SKILL.md。

### 改进点
 - 修改补充了原版缺少的风险分级、准入结论、业务规则一致性、状态与数据边界、验收标准及需求追踪能力
 - 增加是否基于RAG、设计稿来分析

推荐提示词模板：
```

# 基础模式：仅评审需求

请读取并使用 Skill：
.\review-product-requirements\SKILL.md

工作模式：基础模式

需求文档：
<需求文档路径>

请检查：
1. 不明确、模糊和存在多种解释的描述
2. 遗漏、重复和互相冲突的需求
3. 角色权限、业务规则、数据规则和状态流转
4. 主流程、异常流程、边界条件和外部依赖
5. 性能、安全、兼容性、可访问性等非功能需求
6. 不可测试或缺少验收标准的内容

不要启用设计稿或 RAG 检查。

输出问题分级、澄清问题、优化后的需求、Given/When/Then
验收标准、测试重点和是否可以进入开发的结论。

报告保存到：
<评审报告输出路径>


# 需求 + 设计稿模式
请读取并使用 Skill：
.\review-product-requirements\SKILL.md

工作模式：需求 + 设计稿

需求文档：
<需求文档路径>

设计稿：
<设计稿目录、图片、PDF、Figma或原型链接>

请完成：
1. 基础需求质量评审
2. 建立需求与页面、Frame、控件和状态的双向映射
3. 检查需求已说明但设计稿未覆盖的内容
4. 检查设计稿新增但需求没有说明的字段、按钮、限制和流程
5. 检查加载、空、错误、无权限、禁用、取消和成功状态
6. 检查文案、角色权限、数据字段和业务状态是否一致
7. 检查响应式、多平台、无障碍和实现可行性
8. 区分设计中的可见事实、设计标注和推断

不要启用 RAG。

输出设计证据编号、需求设计冲突、设计优化建议、需求优化稿、
验收标准、测试重点和追踪矩阵。

报告保存到：
<评审报告输出路径>

# 需求 + RAG 模式
请读取并使用 Skill：
.\review-product-requirements\SKILL.md

工作模式：需求 + RAG

需求文档：
<需求文档路径>

请完成基础需求质量评审，并结合已配置的 RAG 知识库检索：
1. 现行业务规则和术语定义
2. 角色权限和数据范围
3. 数据字典、状态流转和接口规范
4. 安全、合规和非功能要求
5. 历史需求、线上缺陷和测试案例

要求：
- 每条采用的证据标明文档、版本、更新时间和片段位置
- 区分有效、过期、冲突和低置信度证据
- 发现需求与知识库冲突时，不要自行选择，生成澄清问题
- RAG 未配置或检索失败时，继续基础评审并说明覆盖限制
- 不启用设计稿检查

输出 RAG 覆盖、知识证据、需求问题、优化稿、验收标准、
测试重点和追踪矩阵。

报告保存到：
<评审报告输出路径>


# 完整模式：需求 + 设计稿 + RAG
请读取并使用 Skill：
.\review-product-requirements\SKILL.md

工作模式：完整模式

需求文档：
<需求文档路径>

设计稿：
<设计稿目录、图片、PDF、Figma或原型链接>

请结合已配置的 RAG 知识库，完成需求、设计稿和知识证据的
三方一致性评审。

重点检查：
1. 需求本身的歧义、遗漏、冲突和不可测试问题
2. 需求与设计页面、Frame、控件、流程和状态是否一致
3. 设计新增但需求没有说明的业务规则
4. 需求存在但设计缺少的页面、交互和异常状态
5. 需求、设计稿和知识库中的角色、权限、字段、状态及文案冲突
6. 加载、空、错误、无权限、禁用、取消、超时和成功状态
7. 响应式、多平台、无障碍、安全和实现可行性
8. 历史缺陷是否可能在当前需求或设计中再次出现

所有问题必须关联：
需求编号 → 设计证据 → 问题编号 → RAG证据 → 澄清问题
→ 需求/设计优化建议 → 验收标准 → 测试重点

RAG 或设计稿无法访问时，继续完成其他可用范围，并明确说明限制。

报告保存到：
<评审报告输出路径>

```
