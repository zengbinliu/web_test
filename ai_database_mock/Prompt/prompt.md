# 通用 SQL Agent 用户提示词指南

本指南提供用户提示词模板，Agent 会在运行时读取 `build_table_graph.py` 生成的 `table_graph.json`，以目标数据库的真实元数据为准。

`Prompt/prompt.md` 是用户使用手册，不参与表结构配置。业务规则发生变化时，只需在请求中填写相应占位符内容。

## 一、能力和边界

| 操作 | 支持情况 | 主要限制 |
| --- | --- | --- |
| 查询 | 单表或多表 `SELECT` | 只能使用图谱中的表、字段和关系，单条最多返回 100 行 |
| 单表新增 | `INSERT ... VALUES` | 必须符合字段类型、非空、唯一和外键约束 |
| 多层新增 | 分层数据计划及完整 SQL 预览 | 父子写入只使用数据库真实 `explicit_fk` |
| 更新 | 一条或多条单表 `UPDATE` | 必须包含明确 `WHERE`，不支持多表 UPDATE、ORDER BY、LIMIT |
| 删除 | 一条或多条单表 `DELETE` | 必须包含明确 `WHERE`，多表删除按子表到父表排序 |
| 数据校验 | 使用 `SELECT` 检查完整性、唯一性、引用和一致性 | 业务口径必须由用户明确提供 |

系统拒绝 DDL、`INSERT ... SELECT`、无 `WHERE` 的更新或删除、未知表以及混合操作类型。所有写操作必须先预览，再确认执行；批量写入和分层计划使用同一个事务。

系统会从字段名识别有限的通用测试语义，但不会把它扩展为项目业务规则：

- 表名、字段名、类型、主键、唯一约束和外键来自动态图谱。
- 用户明确给出的值、格式、范围、公式、起点和步长优先，绝不会被字段名推断覆盖。
- 用户未明确时，可识别邮箱、密码/哈希/盐值、电话、URL、IP、金额/价格/成本/费用/余额、数量、材料、快照、行号/序号/排序号、编码和名称等常见英文或中文字段名，并生成类型兼容的测试值。
- 枚举候选值、字段长度、数值精度和数据库约束始终限制最终值；不兼容时系统会拒绝而不是强行生成。
- 状态流转、跨字段计算、比例分布、时间先后、行业编码等规则仍必须由字段注释、数据库约束或用户请求明确。
- 分层计划中，同一个 entity 默认使用一组固定 `values`；数据库生成主键、外键、单列唯一字段、推断字段和递增字段会按规则逐行变化。
- 需要多组不同固定值时，应拆分场景分批生成并分别预览。

## 二、通用迁移步骤

1. 安装目标数据库对应的 SQLAlchemy 驱动。
2. 修改根目录 `.env` 中的 `DATABASE_URL` 和可选 `DB_SCHEMA`。
3. 运行 `python .\build_table_graph.py`。
4. 检查 `table_graph.json` 和 `table_relations.html` 中的表、主键、唯一约束和关系方向。
5. 查询所需的非标准关系可以配置 `RELATION_HINTS_JSON` 后重新建图。
6. 自动补齐依赖和分层写入只信任数据库真实 `explicit_fk`；关系提示不能替代真实外键执行写入。
7. 使用低权限测试账号启动 Flask，先验证只读查询和写入预览。
8. 修改数据库连接或 `.env` 后重启 Flask；只更新图谱文件时 Agent 会自动重新加载。

目标数据库的表注释、字段注释、枚举、默认值和检查约束越完整，生成结果越可靠。

## 三、推荐的请求结构

```text
操作：[查询 / 新增 / 更新 / 删除 / 校验]
业务对象：[业务名称，可附真实表名]
数据范围：[主键、业务键、状态、时间或其他筛选条件]
数量：[总数、每个父对象的子记录数、返回上限]
字段规则：[必填值、唯一格式、枚举、范围、JSON结构]
关联规则：[父子对象以及必须使用的真实外键]
一致性规则：[计算公式、状态组合、时间先后]
预期输出：[返回字段、排序、每层数量、具体SQL]
执行方式：[只查询 / 只预览写入]
```

推荐写法：

- 使用“精确 N 条”或“至少 N 条”，不要只写“多条”。
- 使用已有父记录时，提供明确且可验证的主键或业务键。
- 同时创建父对象和子对象时，把所有对象写在一个请求中。
- 明确哪些字段允许 `NULL`、空文本或数值 `0`。
- 明确唯一字段的格式以及是否由系统生成。
- JSON 字段给出合法 JSON 结构示例。
- 汇总值与明细值有关时，写出完整计算公式。
- 写操作结尾注明“只预览，不要直接确认执行”。

### 3.1 允许系统生成缺省字段值

不关心具体测试值时，可以把这条规则直接写入请求：

```text
用户未明确的普通字段允许系统根据字段注释、枚举、约束、字段名和字段类型生成测试值。
邮箱、密码/哈希/盐值、金额/价格、数量、材料、快照、行号等通用字段使用类型兼容的专用值。
不得覆盖本请求明确给出的值；不得推断状态流转、跨字段公式或其他项目业务规则。
展示补齐后的全部具体 SQL，只预览，不要直接确认写入。
```

也可以显式覆盖某个推断结果：

```text
[邮箱字段]固定为[具体值]；[金额字段]允许为0；[行号字段]从100开始，每条增加10。
以上明确规则优先于任何字段名推断。
```

系统使用的值优先级如下：

```text
用户或计划中的明确值/生成规则
  > 根据字段注释、枚举和检查约束形成的明确值
  > 有限的通用字段名语义
  > 数据库默认值或必填字段的类型兜底
```

普通 INSERT 会在预览阶段展示补齐后的 `planned_sql`；分层新增会在每层计划中列出推断字段并展开全部具体 SQL；自动创建缺失父记录时也使用同一套生成规则。自动密码和哈希只适合测试数据，不可作为生产凭据。

## 四、查询提示词

### 4.1 单表查询

```text
查询[业务对象或真实表名]：
1. 筛选条件：[字段、运算符和值]。
2. 返回字段：[所需字段]。
3. 空值规则：[保留或排除哪些空值]。
4. 排序规则：[排序字段和方向]。
5. 返回数量：[1到100]。
只生成 SELECT，不返回无关字段。
```

### 4.2 多表关联查询

```text
查询[核心结果]，涉及[对象A]、[对象B]和[对象C]：
1. 只使用表关系图已有的关系，不猜测 JOIN 条件。
2. 主体范围：[主表条件]。
3. 关联范围：[子表条件]。
4. JOIN 语义：[无关联记录时保留主体 / 排除主体]。
5. 汇总口径：[去重、计数、求和或平均值公式]。
6. 返回字段：[字段列表]。
7. 排序和数量：[排序规则，最多100条]。
```

### 4.3 聚合查询

```text
按[分组字段]统计[目标指标]：
1. 数据范围：[筛选条件和时间范围]。
2. 指标公式：[例如 SUM([数值字段] * [数量字段])]。
3. 去重口径：[需要去重时说明字段]。
4. 空值处理：[COALESCE规则]。
5. HAVING条件：[聚合后筛选条件]。
6. 返回字段、排序和数量：[具体要求]。
只生成 SELECT。
```

## 五、新增提示词

### 5.1 单表测试数据

```text
为[业务对象或真实表名]精确生成[数量]条测试数据：
1. 唯一字段：[格式、前缀或生成规则]，每条不得重复。
2. 必填字段：[每个字段的值或规则]。
3. 枚举字段：[只能使用表结构中的合法枚举值]。
4. 数值字段：[最小值、最大值、小数位、是否允许0]。
5. 时间字段：[范围和先后关系]。
6. JSON字段：[合法JSON结构]。
7. 可空字段：[允许为空的字段和比例]。
8. 不填写数据库生成的主键、identity、computed 和审计默认字段。
9. 其余已识别的通用字段允许系统按字段名和类型生成，明确值不得被覆盖。
只生成 INSERT ... VALUES，展示补齐后的具体SQL；只预览，不要直接确认写入。
```

### 5.2 使用已有父记录新增子记录

```text
为已有[父对象]创建[数量]条[子对象]：
1. 已有父记录定位条件：[真实主键或唯一业务键]。
2. 子表外键使用图谱中的真实 explicit_fk。
3. 子对象必填字段：[具体值或生成规则]。
4. 唯一字段：[格式或生成规则]。
5. 其他业务规则：[范围、枚举、JSON、时间和一致性规则]。
6. 父记录缺少邮箱、密码哈希等通用字段时，允许系统按字段名和类型生成测试值。
展示自动补齐后的完整SQL；只预览，不要直接确认写入。
```

如果父表主键由数据库生成且父记录尚不存在，应把父对象和子对象放入同一个多层新增请求，不要猜测父主键。

### 5.3 多层测试数据

```text
生成完整的[业务场景]测试数据：
- 精确创建[根数量]个[根对象]。
- 每个[根对象]精确/至少创建[一级数量]个[一级子对象]。
- 每个[一级子对象]精确/至少创建[二级数量]个[二级子对象]。

字段规则：
1. [根对象必填字段和值规则]。
2. [一级子对象必填字段和值规则]。
3. [二级子对象必填字段和值规则]。
4. [唯一字段格式]。
5. [枚举、数值、时间和JSON规则]。
6. [未明确的通用语义字段是否允许系统自动生成]。

一致性规则：
1. [汇总字段] = [明确计算公式]。
2. [父子时间先后关系]。
3. [状态、数量或其他跨字段组合规则]。

关联和输出要求：
1. 只使用图谱中的真实 explicit_fk，禁止猜测父子关系。
2. 数据库生成主键由系统读取并回填到子表外键。
3. 展示每层行数、总行数、分层数据计划和全部具体SQL。
4. 所有层级使用同一个事务，任一条失败时整体回滚。
5. 只预览，不要直接确认写入。
```

### 5.4 需要逐行递增字段

```text
在[子对象]中，[真实数值字段]需要从[起始值]开始、每条增加[步长]：
- 对每个父记录重新从起始值计数；或
- 在该实体的全部记录中连续计数。
其他字段和层级规则与本请求前文一致。
```

常见 `line_no`、`row_number`、`seq`、`sort_order`、`position`、行号或序号字段在没有明确规则时，默认按每个父记录从 1 递增。上面的明确起点、步长和作用域会转换为通用 `sequence` 生成器，并覆盖缺省推断。

### 5.5 需要多组不同值

同一分层实体的一组固定值会重复应用到该实体的所有行。如果需要不同枚举、不同数值区间或不同 JSON 内容，应拆成多个明确场景：

```text
场景A：为[对象]生成[数量]条，字段规则为[规则A]，只预览。
场景B：为[对象]生成[数量]条，字段规则为[规则B]，只预览。
```

## 六、更新提示词

### 6.1 单表更新

```text
更新[业务对象或真实表名]：
1. WHERE条件：[能够明确限定记录的主键、业务键或条件组合]。
2. 修改字段：[字段和目标值]。
3. 排除条件：[必须保留的记录]。
4. 预期影响行数：[已知时填写]。
只生成单表 UPDATE；必须包含 WHERE；展示具体SQL并预览，不要直接确认执行。
```

### 6.2 多表分别更新

```text
对[对象A]和[对象B]分别更新：
1. [对象A] 的 WHERE 条件和修改字段：[内容]。
2. [对象B] 的 WHERE 条件和修改字段：[内容]。
3. 执行顺序：[根据真实关系说明顺序]。
4. 每条语句的预期影响行数：[内容]。
生成多条单表 UPDATE，不使用 JOIN、子查询、ORDER BY 或 LIMIT；统一预览和事务执行。
```

## 七、删除与清理提示词

### 7.1 单表删除

```text
删除[业务对象或真实表名]中满足以下条件的记录：
1. WHERE条件：[明确主键、业务键或条件组合]。
2. 排除条件：[必须保留的记录]。
3. 预期影响行数：[已知时填写]。
只生成单表 DELETE；必须包含 WHERE；展示具体SQL并预览，不要直接确认删除。
```

### 7.2 多表清理

```text
清理一组已明确定位的测试数据：
1. 测试数据标识：[主键、唯一业务键、统一前缀或时间范围]。
2. 涉及对象：[子对象到父对象列表]。
3. 每张表的独立 WHERE 条件：[逐表填写]。
4. 删除顺序：先子表后父表。
5. 排除条件：[必须保留的数据]。
6. 所有语句使用同一个事务。
展示全部具体SQL和预览，不要直接确认删除。
```

当前 UPDATE/DELETE 不支持子查询。多表清理应先通过 SELECT 获得需要操作的具体主键，再使用明确主键生成多条单表 DELETE。

## 八、数据质量校验提示词

### 8.1 完整性、唯一性和引用完整性

```text
校验[业务对象或流程]的数据质量：
1. 完整性：[哪些字段不得为NULL或空文本]。
2. 唯一性：[哪些字段或字段组合不得重复]。
3. 引用完整性：[哪些外键必须找到父记录]。
4. 合法性：[枚举、数值和JSON的合法范围]。
5. 时序性：[开始、结束或父子记录的时间关系]。
返回记录标识、问题类型、当前值和预期规则；每类最多返回20条。
```

### 8.2 汇总与明细一致性

```text
校验[主对象].[汇总字段]是否等于关联[明细对象]的[明确聚合公式]：
1. 只使用图谱中的真实关系。
2. 数据范围：[时间、状态或其他条件]。
3. 空明细处理：[按0处理 / 排除]。
4. 返回主记录标识、当前汇总值、明细计算值和差额。
5. 只返回不一致记录，按差额绝对值倒序，最多20条。
```

## 九、常见失败原因

| 错误或现象 | 常见原因 | 修改方式 |
| --- | --- | --- |
| 找不到表或字段 | 业务名称与数据库名称差异较大 | 在业务对象后补充真实表名或字段名 |
| 找不到关联路径 | 数据库没有外键且命名不规则 | 补建真实外键；只读查询可配置关系提示后重新建图 |
| 分层写入拒绝关系 | 关系不是 `explicit_fk` | 在数据库声明真实外键并重新生成图谱 |
| 缺少必填字段 | 非空且无默认值的字段未提供 | 按错误信息补充字段值或生成规则 |
| 唯一约束冲突 | 多行使用同一个固定唯一值 | 省略该固定值让系统生成，或拆分请求 |
| 业务值不合理 | 字段名只能表达通用语义，不能表达项目规则 | 补充枚举、范围、公式、JSON、状态和时间规则 |
| 更新或删除被拒绝 | WHERE 不明确或使用了不支持的 JOIN/子查询 | 先查询具体主键，再生成单表语句 |
| 总行数超限 | 层级乘法超过 `DATA_PLAN_MAX_ROWS` | 减少数量或在测试库评估后调整限制 |

## 十、提交前检查表

- 操作类型是否单一且明确。
- 业务对象是否存在于最新图谱。
- 筛选条件、数量和返回上限是否明确。
- 多层数量乘法和总行数是否正确。
- 是否填写非空且无默认值的普通字段。
- 是否说明唯一字段、枚举、范围、JSON和时间规则。
- 是否允许系统推断通用缺省字段，以及哪些字段需要显式覆盖。
- 跨字段或跨表计算公式是否明确。
- 写入关系是否为数据库真实 `explicit_fk`。
- UPDATE 和 DELETE 是否包含具体 WHERE。
- 是否要求展示具体 SQL 和预览。
- 写操作是否注明“不要直接确认执行”。
